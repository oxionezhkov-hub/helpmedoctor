# Статья для блога helpmedoctor.ru

Читатель — студент-медик (чаще 3–6 курс), ординатор или молодой врач, который ищет в Яндексе или Google конкретный ответ: к практике, экзамену, аккредитации, дежурству. Статья должна закрыть его запрос лучше, чем первая страница выдачи, и быть такой, чтобы ИИ-поисковики (Алиса, ChatGPT, Perplexity, Google AI Overviews) цитировали её как источник.

## 1. Выбор темы

1. Открой `content/blog-topics.md`. Возьми темы со статусом `[ ]` сверху вниз (выше — важнее). За один запуск — ровно столько статей, сколько попросили.
2. Проверь, что темы нет среди опубликованных: `ls scripts/site/posts/` и `grep -n "slug:" scripts/site/articles.mjs`. Не пиши вторую статью под тот же запрос — каннибализация хуже, чем пропуск.
3. Уточни запрос через WebSearch: как формулируют вопрос, что уже есть в топе, какие подвопросы там не раскрыты. Твоя статья должна быть полнее и практичнее топа, а не пересказом.
4. Если темы в списке кончаются — допиши в конец 10 новых по тем же принципам (реальные запросы студентов-медиков, связь с продуктом: расспрос, диагностика, анализы, клинические задачи, аккредитация, общение с пациентом).

## 2. Требования к тексту

- **Объём:** 1400–2500 слов основного текста. Длина — следствие полноты, не вода.
- **Первый абзац** — `<p class="lead">`: прямой ответ на запрос в 2–3 предложениях. Никаких «В этой статье мы рассмотрим».
- **Структура:** 5–9 разделов `<h2>`, при необходимости `<h3>`. Заголовки — формулировки, которые люди реально ищут («Как отличить…», «Нормы у взрослых», «Алгоритм на станции ОСКЭ»).
- **Форматы, которые любят и поиск, и ИИ:** нумерованные алгоритмы, списки, таблицы (`<table>` с `<thead>`), мнемоники, примеры фраз врача, разборы клинического случая, блок `<p class="note">` для важного предупреждения.
- **Конкретика:** цифры, нормы, дозы, критерии, шкалы — только проверенные, с источником. Если данные различаются между рекомендациями или лабораториями — так и напиши.
- **Никаких выдуманных фактов**, статистики, цитат, исследований и «по данным учёных» без ссылки. Сомневаешься — не пиши.
- **Без переспама:** ключевую фразу используй естественно — в title, h1, лиде, одном-двух h2 и по смыслу в тексте. Синонимы и связанные термины (LSI) вместо повторов. Тест упадёт, если одно слово занимает больше 2,5% текста.
- **Тон:** как опытный старший коллега — прямо, по делу, без канцелярита и без англицизмов там, где есть русский термин. Обращение на «вы».
- **Медицинская безопасность:** статья учебная; не давай персональных назначений читателю-пациенту. Для тем про лечение — формулировки «по клиническим рекомендациям назначают…», а не «принимайте».
- **Продукт:** один естественный абзац-мостик в конце (или в тексте, где уместно) о том, как навык из статьи тренируется в «Help me, Doctor» — без рекламных восклицаний. CTA-блок сайт добавляет сам.
- **Перелинковка:** 2–4 ссылки на другие статьи блога (`<a href="/blog/<slug>/">…</a>`) там, где это помогает читателю. Только на существующие slug.
- **Иллюстрации:** если уместна схема — добавь её в `scripts/site/figures.mjs` (HTML/CSS, по образцу существующих) и вставь меткой `<!--fig:имя-->`. Не больше двух на статью.

## 3. GEO-блоки (обязательно)

- `summary` — 3–5 пунктов «Коротко»: самостоятельные утверждения с фактами, каждое можно процитировать отдельно.
- `faq` — 3–6 пар `[вопрос?, ответ]`: вопросы, которые люди задают дополнительно (смотри «Люди также спрашивают» в выдаче). Ответ — 2–4 полных предложения, 60+ символов, самодостаточный.
- `sources` — 2–6 источников `[название, https-ссылка]`: клинические рекомендации Минздрава (cr.minzdrav.gov.ru), ФМЗА / Методический центр аккредитации (fmza.ru), ВОЗ, профильные общества, учебники (без ссылки можно: `["Пропедевтика внутренних болезней, под ред. Ивашкина", ""]`). Каждую ссылку проверь (`curl -sIL <url>` — статус 200, либо WebFetch) — битые не ставь.

## 4. Файл статьи

Создай `scripts/site/posts/<slug>.mjs` (имя файла = slug, латиница через дефис, транслит запроса, 2–5 слов):

```js
export default {
  slug: "rasshifrovka-ekg",
  date: "YYYY-MM-DD",               // сегодняшняя дата (МСК)
  title: "…",                        // до 70 символов, ключевой запрос в начале — для <title>
  h1: "…",                           // до 90 символов, может отличаться от title
  description: "…",                  // 120–170 символов: ответ + польза, для сниппета
  minutes: 9,                        // ≈ слов / 180
  tags: ["экг", "кардиология"],      // 2–5, строчными; используй уже существующие теги, где подходят
  cover: {
    hue: 200,                        // оттенок фона 0–360, отличный от соседних статей
    tag: "ЭКГ",                      // короткая плашка на обложке
    patient: { s: "cover-<slug>", g: "m", a: 61, m: "bad" },   // лицо пациента: seed, пол m/f, возраст, m: good|bad
    doctor: { s: "doc-<имя>", g: "f", a: 29, m: "good" },
    says: ["Реплика пациента по теме…", "Вопрос врача?"],        // по 25–45 символов
  },
  summary: ["…", "…", "…"],
  body: `
<p class="lead">…</p>
<h2>…</h2>
…
`,
  faq: [["…?", "…"], ["…?", "…"], ["…?", "…"]],
  sources: [["…", "https://…"], ["…", "https://…"]],
};
```

В `body` — чистый HTML: `<p>`, `<h2>`, `<h3>`, `<ul>/<ol>/<li>`, `<table>`, `<strong>`, `<em>`, `<a>`, `<p class="lead">`, `<p class="note">`. Без `<h1>`, `<script>`, `style="…"`. Экранируй обратные кавычки и `${` внутри шаблонной строки.

## 5. Сборка и проверка

```bash
npm ci                                     # если ещё не установлено
npm i --no-save playwright                 # для обложек; браузер уже есть в окружении (/opt/pw-browsers)
node scripts/build-images.mjs <slug1> <slug2> <slug3>   # обложки только новых статей; если Chromium не найден — CHROME_PATH=/opt/pw-browsers/chromium
node scripts/build-site.mjs                # страницы, sitemap.xml, llms.txt
npm test                                   # в т.ч. редакционные проверки статей
```

Тест «статьи блога … отвечают редакционным требованиям» проверяет объём, структуру, FAQ, источники, переспам, внутренние ссылки и обложки — исправляй текст, а не тест. Открой одну из готовых страниц `public/blog/<slug>/index.html` и перечитай статью целиком глазами читателя: нет ли повторов, воды, ошибок, обрывов.

## 6. Отметить и опубликовать

1. В `content/blog-topics.md` отметь взятые темы: `[x]` и допиши ` → /blog/<slug>/`.
2. Коммит одним сообщением «Блог: <три заголовка через ;>».
3. Публикация — по инструкции рутины (ветка, PR, мерж после зелёного CI). Деплой сам сообщает поисковикам о новых адресах через IndexNow.
