# 7. Структура кампании и загрузка

## Структура

- **Кампания** — одно направление бизнеса и один бюджет. Поиск и сети — разными кампаниями или с выключенными сетями на старте.
- **Группа** — одна задача клиента, свои фразы, регионы, посадочная.
- **Объявления** — 1 комбинаторное или 2–3 обычных на группу, с картинкой, быстрыми ссылками и уточнениями.

Уровни и что на них меняется:

| Уровень | Что настраивается |
|---|---|
| Кампания | стратегия, бюджет, минус-слова, запрещённые площадки, расписание показов |
| Группа | регионы, фразы, минус-слова, аудитории, автотаргетинг |
| Объявление | заголовки, тексты, картинка, ссылка, быстрые ссылки, уточнения |

## Тип кампании

- Новые кампании — Единая перфоманс-кампания (ЕПК). В API она создаётся через версию v501: `https://api.direct.yandex.com/json/v501/campaigns`, структура `UnifiedCampaign`.
- Если инструмент MCP умеет только текстовые кампании (v5, `TextCampaign`) — этого достаточно для поиска.

## Порядок загрузки

1. Кампания (стратегия, бюджет, расписание, минус-слова, площадки-исключения).
2. Группы (регионы, минус-слова).
3. Фразы.
4. Картинки → хеши.
5. Быстрые ссылки и уточнения → id.
6. Объявления (тексты, ссылка с UTM, хеш картинки, id быстрых ссылок и уточнений).
7. Отправка объявлений на модерацию.

Каждый шаг пакетом, а не по одному объекту. Ответ API возвращает результат по каждому объекту — ошибка одного не роняет весь пакет, но её надо исправить и догрузить.

## UTM-метки

`?utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}&utm_term={keyword}` — по ним потом сверяешь заявки в CRM с кампаниями.

## Перед загрузкой

- Скрипт проверки текстов прошёл без ошибок.
- Человек увидел и сказал «да» (шаг 5 пути).
- Запись о загрузке готова для `direct/journal.md`.

Сначала можно загрузить в песочницу и проверить, что всё создаётся без ошибок.
